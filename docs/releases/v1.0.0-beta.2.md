# Stacks Shield v1.0.0-beta.2

**v2 protocol — multi-asset shielded pool on Stacks (testnet).**

This release is the **v2 protocol relaunch** on Stacks testnet: a fresh deployment
with a hardened zero-knowledge proof system, multi-asset support (STX, sBTC, USDCx),
and the SDK published at `1.0.0-beta.2`. **Testnet only — not for mainnet.**

---

## Highlights

- **Proof-soundness hardening (circuit version 2).** Every leaf-adding operation now
  binds the Merkle-tree transition — the new tree root and the exact insertion
  index — *into* the zero-knowledge proof, and each pool asserts the on-chain slot
  matches the proof. The resulting root is now **proven, not merely asserted**. This
  is a significant soundness improvement over v1 (which is superseded — see below).
- **Multi-asset.** STX, sBTC, and USDCx share one privacy pool with asset-bound
  commitments; the full lifecycle — **shield → transfer → split → merge → withdraw** —
  works for each.
- **Validated end-to-end on live testnet.** The complete lifecycle passes for all
  three assets with **real UltraHonk proofs verified via zkVerify**, including
  cross-asset isolation, replay protection, and value conservation.
- **Dedicated relayer set** for privacy-preserving submission (the chain never sees
  the user's address).
- **SDK** `@stacks-shield/sdk@1.0.0-beta.2` published to npm (beta).

## What's changed

- **Circuits / protocol:** v2 circuit family at `circuit_version = 2` binds
  `new_root` + `leaf_index`; the pools and split-merge-manager fold them into the
  public-inputs hash and assert the registry-assigned slot equals the proof-bound
  index.
- **Contracts:** `privacy-registry`, `privacy-pool`, `split-merge-manager`,
  `sip10-pool` updated for v2; the STX withdraw recipient guard hardened for parity;
  misleading root-binding comments corrected.
- **SDK:** insertion-witness proving, v2 canonical public-input encoding (native +
  SIP-10), and all clients repointed to the v2 deployment.
- **Relayer / API:** leaf-index threading through the relayed operations; environment
  templates repointed to v2.
- **Deploy tooling:** a single `.env.v2.deploy` drives a fresh v2 deployment;
  wallet-generation and relayer-provisioning scripts added; verification-key
  generation covers both circuit families.
- **Tests:** contract, attack, integration, SDK, and relayer suites updated to the v2
  ABI (all green).

## Breaking changes

- **New deployment address.** Integrations must target the v2 deployer,
  `ST18XMPE0PS5VNEEKB82BPW7NRZRHXEPH16JK8NN6`. The bundled SDK (`beta.2`) already does.
- **Circuit version 2.** v1 proofs are not compatible with v2 (and vice versa); a v2
  client must be used against the v2 deployment.

## Security & status

- **Testnet only. Not production-ready.** This release has **not** been audited by an
  independent third party. An **independent external audit is required before any
  mainnet deployment.**
- An **internal security review** has been completed for the on-chain core, circuits,
  and SDK cryptography.
- **Known, disclosed trust assumption:** on-chain publication of zkVerify aggregation
  roots is currently a **trusted relayer role**. A threshold (**M-of-N**) publisher
  scheme run by **independent operators** is planned to remove this. Until then, do
  not treat root publication as trustless.
- Do not describe this release as "audited" or "trustless." Use at your own risk.
